# 通訊記錄與可選音訊

音訊 USB 配置白名單支援 `diag,serial,rmnet,ffs` 和 `diag,serial,ecm,ffs`。初始化僅在目前組合後臨時追加 `audio`，停止時恢復本次會話開始時讀取的原組合；不為啟用音訊切換 ECM／RMNET。兩種配置的校驗與恢復邏輯已有迴歸測試，ECM 下的真實音訊和網路並行仍需裝置驗收。

模組通話音訊（背景準備、撥號時連接電腦音訊）屬於實驗功能，目前 Windows 版不支援；撥號、接聽、掛斷等通話控制不受影響。

音訊初始化會先驗證已支援的韌體、核心、USB 標識和啟動 ID，再檢查 ADB UID。非 root 時僅嘗試標準 `adb root`，等待同一 USB 位置、同一次裝置啟動重新連線並確認 UID 0 後才上傳驅動；不自動開放 ADB、不繞過授權、不解鎖或刷寫韌體。韌體禁止 root 或尚未授權時停止並提示。

Web 需先點選「開啟來電／簡訊提示音」，並保持頁面開啟；瀏覽器背景節流會延遲提示，多個分頁同時開啟可能各自提示。既有簡訊不重放提示；舊時間戳簡訊（早於本次服務啟動 30 秒）不觸發提示。提示不包含號碼或簡訊正文，不儲存錄音。

Web 簡訊頁的「按卡記錄」與電話頁的「最近通話」共享本機歷史儲存。可檢視目前卡、全部卡片、指定 ICCID 尾號或未歸屬記錄，每頁 100 條，可繼續載入；換卡不會刪除舊記錄。號碼僅作為記錄欄位，不作為卡片身份。

歷史儲存在 `%APPDATA%\DJ4Hub\communication-history.sqlite`（SQLite，**未加密**，權限沿用使用者設定檔目錄的 ACL）。無需安裝資料庫服務。僅允許一個後端行程持有歷史儲存（以 `LockFileEx` 互斥），相容舊 JSON 版本的鎖定檔，避免兩個版本同時寫入。

新版服務首次啟動會在事務中匯入同目錄的 `communication-history.json`，匯入記錄和完成標記一起提交。原 JSON 原樣保留作遷移前備份，後續啟動不會重複匯入或覆蓋資料庫的新記錄；無舊檔案則直接建立資料庫。JSON 損壞或存在衝突 ID 時停止啟動並回滾匯入，不覆蓋原檔案。SQLite 開啟 WAL 和 FULL 同步，按 ICCID / 型別建立索引並在資料庫中分頁。備份執行中的資料庫應使用 SQLite 線上備份工具，不能只複製主檔案而遺漏 WAL；也可先停止服務再複製。舊 JSON 不包含遷移後的新增記錄，不能用它直接回退最新資料。請勿將歷史檔案上傳倉庫或用作公開示範素材。

歸屬採用操作前後均成功讀取且一致的 ICCID；eSIM 按 Profile 的 ICCID 區分。SIM 儲存（SM）讀取的簡訊可歸屬目前卡；模組儲存（ME）及串列埠回撥無法證明原始卡片身份，保守放入「未歸屬」。舊收件匣仍是模組讀取快取，按卡歷史為獨立入口。傳送記錄的“已提交模組”不代表對方送達，失敗可能包含部分分段已傳送。歸檔失敗時自動清理模組簡訊會停止。

通話記錄來自軟體執行期間的 CLCC 觀測（約 3 秒一次及撥號/掛斷時查詢），不是電信業者賬單，極短來電可能漏記，時長為估算值。查詢中斷或重啟會標記“記錄中斷”，不會捏造結束時間；不能補回此前在其他手機上的歷史。模擬模式不寫真實歷史檔案。


## 雲盤備份

主資料庫保持本地。快照備份與合併恢復的後端 API 仍保留（使用 VACUUM INTO 產生包含已提交 WAL 內容的完整快照，而非複製正在寫入的主檔案），但設定介面原本位於 macOS 原生 App，Windows 版尚未提供。備份未額外加密。

## ICCID 填充相容

部分模組將 BCD 填充字元 F 一併返回。歸檔讀取會去掉單個末尾 F/f 後驗證數字卡號；中間夾雜字元、多個填充或長度不合規則拒絕歸屬。仍要求操作前後的 ICCID 一致，不會透過 IMEI、裝置序列號或電話號碼猜測卡片身份。此前未歸屬記錄保持原狀，可在“全部 SIM 卡／未歸屬”檢視。
